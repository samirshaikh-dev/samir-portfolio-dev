# Code Review Graph — What is it?

Open source

AI developer tool

MIT License

Code Review Graph is an AI-powered codebase intelligence tool that helps AI coding assistants understand large projects without repeatedly reading the entire codebase.

GitHub: [tirth8205/code-review-graph](https://github.com/tirth8205/code-review-graph?utm_source=chatgpt.com)

## 1. What problem does it solve?

Imagine you're working on your meelTe Next.js project.

You ask Cursor:

> Find why the footer component is breaking and identify other components that might be affected.

Without Code Review Graph:

- AI searches through files.
- Reads multiple components.
- Tries to understand imports and dependencies.
- May miss indirect dependencies.
- Consumes more context tokens.

With Code Review Graph:

- Builds a structural map of your codebase.
- Understands imports, functions, classes and dependencies.
- Identifies affected components.
- Gives AI relevant code context.

Think of it as a searchable dependency brain for your project.

1. Parse: Tree-sitter analyzes your source code.
2. Build graph: Creates relationships between functions, classes, imports and tests.
3. Store: Saves the graph locally in SQLite.
4. Analyze: Identifies dependencies and potential impact of code changes.
5. Connect: Exposes relevant information to AI coding assistants through MCP.

## 3. Installation on Windows

Open PowerShell:

```
pipx install code-review-graph
```

Then navigate to your project:

```
cd path\to\your\meelTe-project
```

Install AI tool integrations:

```
code-review-graph install
```

Or configure Cursor specifically:

```
code-review-graph install --platform cursor
```

Build your codebase graph:

```
code-review-graph build
```

Restart Cursor after installation.

## 4. Important commands

| Command          | Purpose                        |
| ---------------- | ------------------------------ |
| `build`          | Build codebase graph           |
| `update`         | Update changed files           |
| `status`         | Show graph statistics          |
| `watch`          | Watch file changes             |
| `visualize`      | Visualize codebase graph       |
| `dead-code`      | Find potentially unused code   |
| `wiki`           | Generate project documentation |
| `detect-changes` | Analyze changes and risks      |
| `forget`         | Remove parsed files from graph |

Example:

```
code-review-graph status
code-review-graph visualize
code-review-graph dead-code
code-review-graph detect-changes --brief
```

## 5. Code Review Graph vs Graphify

Since you were also exploring Graphify, here's the distinction:

| Feature                    | Code Review Graph     | Graphify                    |
| -------------------------- | --------------------- | --------------------------- |
| Main purpose               | Codebase intelligence | Knowledge graph             |
| Code dependencies          | Yes                   | Not its primary focus       |
| Impact analysis            | Yes                   | Not its primary focus       |
| Dead-code detection        | Yes                   | Not its primary focus       |
| AI integration             | MCP                   | AI-oriented graph workflows |
| Architecture understanding | Yes                   | Yes, depending on workflow  |

Now that Code Review Graph is installed and its CLI works, the next step is to connect it to your AI coding agent.

Your goal is to make Cursor and other AI agents access the same codebase knowledge graph, so they can understand dependencies, inspect code relationships, and analyze changes without rebuilding that understanding from scratch.

There are two ways to use it:

1. CLI: You manually run commands in PowerShell.
2. MCP integration: Your AI agent calls Code Review Graph tools directly while working on your project.

I recommend setting up both.

## 3. Give your AI agent instructions

After connecting, try this prompt in Cursor Agent:

Use Code Review Graph as your primary codebase intelligence tool.

Before making changes:

1. Inspect the existing codebase graph.
2. Understand the architecture, modules, dependencies, and execution flows relevant to the task.
3. Identify affected components and dependencies before modifying files.
4. Use graph-based context to avoid unnecessary repository-wide exploration.

When making changes:

1. Consider the impact on dependent components.
2. Identify potentially affected tests.
3. Follow the existing architecture and coding conventions.
4. Avoid unnecessary refactoring.

After making changes:

1. Update the code graph if needed.
2. Analyze the change impact and potential regressions.
3. Report affected files, dependencies, and testing recommendations.

Do not assume the graph contains up-to-date information. Check its status when necessary.

## 4. Use Code Review Graph directly from CLI

You can run these commands whenever you need them.

| Command          | What it does                        |
| ---------------- | ----------------------------------- |
| `build`          | Rebuild entire graph                |
| `update`         | Update only changed files           |
| `status`         | Check graph health/statistics       |
| `visualize`      | Open graph visualization            |
| `wiki`           | Generate architecture documentation |
| `detect-changes` | Analyze change impact               |
| `watch`          | Automatically monitor file changes  |

Your Windows commands:

```
# Update graph
python -m code_review_graph update

# Check graph
python -m code_review_graph status

# Analyze recent changes
python -m code_review_graph detect-changes --brief

# Watch project changes
python -m code_review_graph watch
```

The graph is stored locally in `.code-review-graph/`. Incremental updates help keep it synchronized.&#x20;
