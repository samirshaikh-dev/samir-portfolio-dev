## Projects page layout

Create one `/projects` page with two sections:

```text
Projects
My independent builds, experiments, and engineering work.

[All] [Projects] [Case Studies]
```

Then display:

### Selected Projects

Use this for smaller or medium-sized work:

- UI experiments.
- Frontend applications.
- Open-source contributions.
- Small automation tools.
- Design experiments.
- Proof-of-concept builds.
- Projects without extensive documentation.

Card format:

```text
Project title
Short description
Personal project
React · Node.js · PostgreSQL

[Live Demo] [GitHub]
```

### Selected Case Studies

Use this for your strongest and most technically detailed projects:

- Eventify.
- WhatsApp Campaign Automation Platform.
- AI Customer Ticket Triage.

Card format:

```text
AI Customer Ticket Triage
LLM-powered support-ticket classification system
Personal project · Case study

AI Agents · Microservices · Redis · BullMQ

[Read Case Study]
```

## Optional filtering

A filter bar would work well:

```text
All    Projects    Case Studies    AI    Automation    Full Stack
```

When the user selects **Case Studies**, show only your detailed project breakdowns. When they select **Projects**, show the regular project cards.

Avoid making “Projects” and “Case Studies” separate unrelated pages if the content overlaps. A filter or clearly separated sections gives visitors one predictable place to explore your work.
